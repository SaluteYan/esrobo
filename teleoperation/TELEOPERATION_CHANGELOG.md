# 遥操作重要更改记录

本文件记录会改变实机运动、标定或安全行为的重要修改。详细启动步骤和命令仍以
`TELEOPERATION_RUNBOOK.md` 为准。

## 2026-09-14：降低全臂跟随延迟

- 根据应用第一轮加速参数后的右臂实测继续调整：J3 从约 `57.1 deg` 回到 `3.8 deg` 用时
  约 `14 s`，平均速度已从约 `1.65 deg/s` 提高到约 `3.8 deg/s`，但 SDK `15% move_j`
  仍明显低于软件速度上限，因此将平滑档位提高到 `25%`。
- 取消实时跟随中的七轴统一完成比例。实测 J3 误差约 `57 deg` 时，只有约 `5.6 deg` 误差的
  J1 被比例同步压低至约 `0.4 deg/s`。现在各轴独立执行速度和加速度限制，解决肩部小角度
  目标被其他大误差关节拖慢的问题；软限位和回零到位确认不变。
- J1/J2/J3 跟随上限统一提高到 `18 deg/s`，J4-J7 为 `20 deg/s`；加速度调整为
  `45/45/50/60/60/60/60 deg/s^2`，单步兜底为 `2.2/2.2/2.2/2.5/2.5/2.5/2.5 deg`。
- 肘腕同步目标平移上限由 `0.14 m/s` 提高到 `0.18 m/s`，减少重定向层在正常抬臂动作中
  持续积累的位置滞后；肘腕仍共用骨架推进比例并保持机器人连杆长度。
- 根据最近一次右臂回零反馈复核限速链路：J3 从约 `58.4 deg` 回到 `8.8 deg` 用时
  `30 s`，平均约 `1.65 deg/s`；PICO 输入同期保持约 `55~77 Hz`，因此主要瓶颈不是
  采集网络，而是按固定 `50 Hz` 设置的单反馈步长遇到约 `10 Hz` CAN 反馈后形成额外限速。
- 将单步上限调整为 J1/J2 `1.5 deg`、J3 `1.8 deg`、J4 `2.2 deg`、J5-J7 `2.5 deg`。它现在只负责
  拦截反馈停顿后的异常单次跳变，正常速度继续由实际反馈 `dt`、逐轴速度和加速度约束。
- 左右臂统一提高跟随上限：J1/J2 `12 deg/s`，J3 `15 deg/s`，J4 `18 deg/s`，J5-J7
  `20 deg/s`；对应加速度为 `30/30/40/50/60/60/60 deg/s^2`。J4 单独略快，用于减少
  人体肘屈曲变化时小臂目标的滞后。
- 肘腕同步平移上限从 `0.10 m/s` 提高到 `0.14 m/s`，仍保持肘点和腕点共用进度，避免
  只加快腕点造成前臂长度或肘角瞬时失真。
- SDK 平滑 `move_j` 速度从 `10%` 调整为 `15%`。左臂静默失能唤醒仍以最多 `10%`
  执行；确认七轴自然下垂零位反馈后才恢复 `15%`，避免提高启动接合速度。
- 关节软限位、左右方向/偏置、同步运动、IK目标约束和两阶段回零顺序均未改变。

## 2026-09-14：退出与保护回零确认

- 修复IK每帧都从低速实体反馈重新求解、导致网页 `IK结果` 被机械臂反馈拖慢的问题。现在从
  上一帧IK目标连续求解，并将计算目标限制在实体反馈每轴 `+/-0.50 rad` 内；静态离线目标在
  约2-3个计算周期内收敛，最终实机命令仍经过关节同步速度、加速度、单步和软限位。
- 保留每周期一次Pink求解。离线对比发现盲目增加单帧内部迭代不能稳定降低加权肘腕误差，
  因此采用跨周期连续种子，而不是增加同一帧的无效计算。
- 为减少不同关节独立限速造成的姿态变形，增加七轴统一进度限制。正常跟随时所有活动关节按
  各自目标误差的同一比例推进，公共进度同时满足逐关节速度、加速度和单步上限；方向反转时
  仍优先限加速度减速，不会为同步运动跳过安全约束。
- J1/J2 跟随速度从 `5 deg/s` 提高到 `7 deg/s`，J3/J4 从 `6 deg/s` 提高到 `8 deg/s`；
  对应加速度提高到 `14/16 deg/s^2`，J5-J7 保持 `12 deg/s` 和 `24 deg/s^2`。同步肘腕
  平移上限由 `0.08 m/s` 提高到 `0.10 m/s`。
- 修复重定向层只限制腕点、肘点立即跳到新目标造成前臂方向和 J4 夹角短时失真的问题。肘点
  和腕点现在共用同一个运动进度，限速过程中持续保持机器人固定的大臂和前臂长度，并保证
  两个点各自的平移速度都不超过当前配置的 `0.10 m/s`。
- 将全臂遥操作调整到第二阶段联调范围：J1/J3/J5 软限位扩大到 `+/-60 deg`，J2 扩大到
  `-75~+7 deg`，J4 扩大到 `-8~+85 deg`，J6 扩大到 `-30~+35 deg`，J7 扩大到
  `+/-55 deg`。这些仍是 URDF 软限位，SDK 硬限位和 `0.05 rad` 余量保持不变。
- 左右单臂和双臂跟随速度统一提高为 J1/J2 `5 deg/s`、J3/J4 `6 deg/s`、J5-J7
  `12 deg/s`；对应最大加速度为 `10/12/24 deg/s^2`，单反馈步长为
  `0.10/0.12/0.24 deg`。该阶段末端平移速度限制为 `0.08 m/s`，随后已提高到 `0.10 m/s`。
- 按实机防跌落要求，删除全臂回零未确认后的自动保护失能。回零超时、反馈丢失或关节未连续
  确认到位时，程序停止跟随并锁存当前使能状态，不再发送失能命令；操作员继续托稳并按 `s`
  重试回零、按 `d` 明确失能或按 `x` 急停。
- 全臂模式按 `q` 后若回零未确认，不再退出或断开驱动，而是取消退出并留在人工接管等待状态；
  只有回零成功且失能得到确认，程序才正常关闭通信。故障锁存期间拒绝按 `e` 恢复跟随。
- 修复右臂第一阶段 J4-J7 尚未通过到位确认时立即失能、导致 J1-J3 在重力下落而看起来像
  “直接回零”的问题。每个阶段现在最多执行两次完整的限速回零尝试；重试前主动请求 CAN
  上报并清除上一阶段速度状态，只有 J4-J7 确认到位后才启动 J1-J3 回零。
- 回零期间每秒输出当前阶段各关节相对零位的误差；超时、反馈中断或反馈间隔无效会显示明确
  原因。短暂 CAN 反馈间隙容忍时间由 `0.5 s` 调整为 `1.0 s`，运动限速、限加速度、单步
  限制和连续三帧到位确认保持不变。
- 修复回零过程中单次 CAN 反馈或命令节拍缺失就立即结束回零、随后自动失能的问题。现在允许
  短暂反馈间隙，恢复后继续使用原有限速、限加速度和单步限制回零。
- 末端 J5-J7 或全臂回零进入容差后，必须连续取得 `3` 帧新鲜反馈才判定到位，避免使用单帧
  反馈过早失能。
- 全臂仍按 J4-J7、J1-J3 两阶段回零，但第二阶段会复核 J1-J7 全部关节，防止末端关节在近端
  回零期间偏离后仍被判为完成。
- 修复两个回零阶段复用实时跟随全局反馈时间戳的问题。每个阶段现在先以新鲜反馈保持当前
  姿态，再使用该阶段独立的反馈时间和实际 `dt` 生成限速轨迹，避免 J4-J7 到位后 J1-J3
  因时间戳不递增而没有收到受控回零命令。
- 若反馈持续丢失、回零超时或控制命令持续失败，程序显示 `ZERO RETURN NOT CONFIRMED`，
  锁住跟随并保持使能，等待操作员按 `s`、`d` 或 `x` 处理。

## 2026-09-14：PICO 骨架网页显示方位

- “PICO 原始”层保持原有 PICO/Unity 点映射和观察相机，不再应用 PICO 到机器人固定旋转，
  因而左右臂的原始采集运动不会被机器人坐标观察方向再次投影。
- “固定映射”及重定向、IK、命令、反馈层使用机器人正面观察方位。切换数据层时相机会切换到
  对应坐标系的默认观察方向，避免把原始采集显示与机器人映射显示混为一条变换链。
- Three.js 和 OrbitControls 改为显式相对模块路径，避免不支持 import map 的浏览器无法创建页面。
- 本次变更只影响只读诊断网页，不修改发往遥操作核心的 PICO UDP 数据、标定、IK 或实机命令。

## 2026-09-14：左机械臂与左灵巧手联动模式

- 新增独立启动脚本 `scripts/run_pico_left_arm_hand_teleop.sh`。该模式只初始化左机械臂、
  左灵巧手和左 SenseGlove，不连接右侧机器人硬件。
- 输入职责固定为：PICO 左肩/肘/腕位置控制 J1-J4；左手套 IMU 控制 J5-J7；左手套手指
  姿态控制左灵巧手十个主动关节。
- 每次组合启动强制重新进行左手套六步标定。第 1 步同时确定手指张开端点、手套 IMU 零点
  和掌心朝向身体的初始方向；第 2-4 步识别本次手套开机后的 IMU 坐标基；第 5 步采集
  拇指与食指对指；第 6 步采集握拳和手指屈曲端点。
- SenseGlove 桥已标记为标定零点的数据不再在 PICO 机器人参考重设时二次归零。PICO 标定只
  对齐人体手臂位置和机器人 FK，不改变第 1 步确定的手套 IMU 零点。
- 增加全臂 IMU 旋转补偿。程序先根据 PICO 目标求 J1-J4，并计算这些关节已经带给机器人
  掌心的世界坐标旋转；随后从手套 IMU 的目标掌心姿态中扣除该旋转，只把剩余腕部相对
  旋转映射到 J5-J7，避免手臂摆动被末端关节重复执行。
- `e` 改为联动使能：PICO、手套 IMU、手指目标和左灵巧手反馈必须同时新鲜。任一检查失败，
  左臂和左手都不会进入跟随。
- 联动过程中，PICO、手套 IMU、手指目标、灵巧手反馈或机械臂反馈任一中断，都会停止手指
  跟随，并触发左臂受控回零失能；反馈无效时不盲目发送回零位置。
- `s` 停止联动后，左臂先让 J4-J7 回零，再让 J1-J3 回零并失能，随后左灵巧手缓慢恢复
  自然张开姿态。`q` 使用相同的正常退出顺序；`x` 立即急停左臂并冻结灵巧手目标。

## 2026-09-14：单臂映射与退出安全

- 单臂 PICO 模式直接从目标和反馈骨架夹角差计算 J4，避免肘部屈曲被 IK 分摊到 J1-J3。
- 右臂 J3 使用与 URDF/SDK 同向的配置 `right_joint_directions=[1,1,1,1,1,1,1]`。
- 全臂正常回零改为先 J4-J7、后 J1-J3；第一阶段未确认时不继续移动近端关节。
