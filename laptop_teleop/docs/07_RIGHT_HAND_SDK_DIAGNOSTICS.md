## 整体复核及拇指三轴复测

### 已修复的代码问题

1. L10 CAN `process_response` 原先不区分本机其他 CAN socket 发出的 TX 帧和硬件 RX 回复，可能让目标覆盖反馈缓存。现过滤 `is_rx=False`、错误帧、远程帧、扩展帧、空帧及长度不符的位置帧。
2. SDK 原先可无限重复发布缓存位置并附新 ROS 时间戳。现记录 0x01/0x04 的硬件接收时刻，只有两半位置反馈均在 150 ms 内更新才发布位置状态。
3. `return_to_open` 原先只在开始时检查反馈。现每个渐变周期检查，过期立即停止继续发送。

前两项已同步 src/build 并重启手部 SDK 生效；此前的设置话题左右过滤也已随重启生效。第三项已同步网关所用源码，当前网关仍保持 FAULT、未重启，下一次正常启动加载。既有自然张开目标及容差不变。这些修复改善反馈可信度与保护，不应被描述为已经消除屈伸不到位问题。

### 新测试结果

- 侧摆（索引 1）：210 → 195 → 210，反馈到位。
- 旋转（索引 9）：33 → 48 → 33，反馈到 47 后回到 33。
- SDK 过滤修复重启后，屈伸（索引 0）：136 → 123 → 151 → 136，反馈分别到 123、139、137。目标 151 持续四秒时，反馈恒为 139，速度字段为零。
- 在上述上行保持阶段，SDK 电流原始值为 11～206，温度字段由 35℃升至 41℃；下行至 123 时电流原始值为 0～2。未确认电流单位，不得将这些数值标成 mA。
- 单轴侧摆、旋转测试中屈伸反馈保持约 136，未见超过测试阈值的串动。

这是伸展方向承受负载/内部限制的证据，不足以区分机械传动、固件限位和位置标定。不能用更大目标、提高力矩或将 136 写成张开零位来“修复”。原始记录：`right_thumb_axis_1_result.json`、`right_thumb_axis_9_result.json`、`right_thumb_after_filter_result.json`（均在 laptop_teleop/log）。

## 右拇指可见动作复测

先将右拇指屈伸轴力矩限制设为 60，尝试 137 → 110 → 137；反馈保持 137，说明该力矩不足以驱动当前机构，测试随即中止并把该轴力矩重新置零。

随后按原配置力矩 180 复测相同范围。屈曲目标 110 的渐变末及保持后反馈均为 110；返回目标 137 时渐变末及保持后反馈均为 135。其余右手关节变化不超过 3 单位，左手未发生联动，十轴故障码均为零。屈曲过程中第一轴电流原始峰值为 44；结束时为 1，温度由 35℃变为 36℃。程序退出前再次将右拇指屈伸轴力矩限制设为 0。

这次反馈证明右手第一轴可以在 110～137 的屈曲区间内往返，但不能推翻此前向 151 及自然张开目标 254 运动时的停滞、较高电流和升温结果。实物是否出现与反馈一致的清晰屈曲和回位仍以操作者现场观察为准。当前网关保持 FAULT，遥操作计算停止，双臂七轴反馈均为失能。原始记录：`laptop_teleop/log/right_thumb_visible_retest_result.json`。

诊断脚本结束时曾按保护策略把右拇指第一轴力矩设为 0。随后直接从网页执行正式准备，程序仍要求旧开位 254，但运行中的手部节点不会在每次网页使能时重新初始化力矩，因此反馈保持 139 并再次报错。现已通过带左右侧过滤的 ROS 设置话题把右手十轴恢复为标准力矩 180；此操作没有发送位置指令，恢复前后反馈完全不变。日志中的 `current=139` 原意是当前**位置**而非电流，代码已改为 `position=139`。

恢复力矩只消除了诊断脚本的残留状态，并未修复右拇指此前在正常力矩下向张开方向约 139 处停滞的问题。禁止把反馈零位从 254 改为 139 或跳过开位核验。再次执行正式使能仍可能顶住同一位置；在确认右拇指内部限位、传动和位置标定前，不继续向 254 重复施力。

## PICO 右手遥操作碰撞与频率误停

右手仅灵巧手遥操作曾持续 ACTIVE 约 31 秒，随后本机报告 `control rate 39.9 Hz below required 40.0 Hz`。该错误来自一秒浮点频率窗口的边界抖动，不是手部碰撞检测。单次映射计算中位数约 0.33 ms，PICO 手指输入约 56～70 Hz。后续又出现 39.5 Hz、37.9 Hz 及两秒窗口 37.7 Hz 的停机；末次会话中本机循环仍约 45.5 Hz，PICO 右手来源率降至约 52 Hz，并出现多次“等待下一帧”。因此仅灵巧手模式保留两秒频率窗口，将容差调为 5 Hz，持续低于 35 Hz 才因平均频率停机；其他模式仍用一秒窗口和 0.5 Hz 容差。80 ms 无目标间隔门禁、100 ms 输入新鲜度和网关目标租约始终独立生效。

同一会话中最危险的右手目标为：食指屈曲轴 255（伸直），拇指侧摆 48、拇指旋转 90，并把未参与主动映射的物理索引 7 从约 109 外力推到 28。碰撞后读取十轴故障码均为 0，温度为 33～39℃。曾尝试增加与食指屈曲联动的拇指运动包络，随后按操作者要求完整撤销；当前拇指运动范围与撤销前一致。后续应改进 PICO 拇指姿态估计和重定向标定，而不是按食指姿态限制拇指自由运动。
