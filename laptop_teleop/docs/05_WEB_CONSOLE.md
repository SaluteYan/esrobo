# 网页遥操作控制台

本文解释网页按钮、模式和状态；每日完整顺序见 [运行手册](03_OPERATION_RUNBOOK.md)，环境安装见 [本机 README](../README.md#环境安装与配置)。

## 启动网页

在仓库根目录运行：

```bash
./laptop_teleop/scripts/run_dashboard.sh
```

打开 **http://127.0.0.1:8080**，保持服务终端运行。启动网页不自动启动设备、使能或运动。重复执行启动脚本会复用已有控制台；后端源码更新后，须结束计算并重启原控制台进程，刷新页面仅更新前端资源。端口被其他程序占用时可用 `--port 8081`。

网页默认 SSH 连接 `esrobo@192.168.10.100`，机器人仓库 `/home/esrobo/Projects/esrobo`，机器人 Python `/home/esrobo/miniconda3/envs/teleop_esrobo/bin/python`；部署常量在 `dashboard.py`，新机器按实际环境修改。

## 页面与模式

| 区域 | 用途 |
| --- | --- |
| 设备与驱动 | 机器人 SSH、CAN 初始化、网关/双手/视觉服务、本机 PC Service 和采集启停。 |
| 遥操作控制 | 模式选择、环境检查、预览、正式计算、人工准备、停止和受检恢复。 |
| 腰部三轴 | 读取反馈、独立使能、小步与角度调整、减速停止。 |
| 实时视觉 | 相机/头部控制，或 PICO 骨架和分层计算结果。 |
| 机器人状态 | 网关阶段、原因、七轴使能、控制器故障、输入年龄和手部状态。 |
| 日志与操作记录 | 采集、本机计算、机器人服务和控制台操作结果。 |

支持单臂＋同侧手、纯单臂、仅单侧灵巧手和双臂模式。仅手模式要求所选 Hand，不要求 Body/IK，机械臂必须始终七轴失能。纯臂模式只要求 Body，实时末端三轴保持实测位置。双臂缺少互碰扫掠检查，自动准备和回零被拒绝。

网关运行时下拉框显示其实际模式并锁定。切换须结束计算、按现场流程停止网关并等待退出，再选择模式启动；下拉框不会改变已运行的进程。

## 连接与服务启动

1. 点击“连接机器人”。首次 SSH 主机密钥先通过终端核对，网页不自动信任未知主机；密码仅用于当前连接，有公钥时可留空。
2. CAN 未就绪时点击“关闭服务并初始化 CAN”。页面先停止计算、请求并核验机械臂失能；腰部正在运行时还须停止并核验三轴停稳，然后关闭相关驱动、网关和手部桥。任一步未确认就中止，不强制重置总线。
3. 带手/仅手模式依次启动“双手 ROS 驱动”“双手通信桥”“双臂遥操作网关”；纯臂可省略双手服务。网关自身持有机械臂驱动，不另启争用 CAN 的控制进程。
4. 查看 `IDLE`、控制器无故障和新鲜反馈。继承电子急停时结束计算，再走受检恢复；CAN 初始化和网关重启均不代表控制器已复位。
5. 本机启动“PICO PC Service”“PICO 全身＋双手采集”。头显佩戴亮屏、追踪应用在前台、Body 与 Hand Tracking 开启。带手模式核对同侧肩肘腕、手指和掌面状态。

相机需要机器人相机驱动与 8766 网页服务，HTTP 经已登录 SSH 通道转发；PICO 骨架来自本机 8765 服务。二者互相独立，SSH 登录成功不证明图像服务已启动。

## 预览、标定与正式运行

先点击环境检查，再预览并完成稳定参考，核对实际计算目标和各层姿态。预览不发送运动目标；结束预览会请求停止，正式运行前须恢复网关 `IDLE`。

正式计算启动后 `IDLE` 只回送实测机器人姿态。人工点击“使能并准备 e”后，自动准备锁定手部实测位置、执行七轴受检回零并验证失能，再进入参考标定。保持期望姿态和完整 PICO 输入，标定平均姿态锁定为首次目标；没有特定抬臂或屈肘角度要求。

| 网关阶段 | 页面应如何理解 |
| --- | --- |
| `CALIBRATING` | 采集稳定参考；100 ms 时效和组件同步有效。 |
| `CHECKING_ENTRY` | 检查锁定目标与路径；只规划 J1–J5，J6/J7 和手指保持实测位置。 |
| `APPROACHING` | 50 Hz 受检接近；独立保活持续，PICO 暂无新帧不改写锁定目标。 |
| `WAITING_FOR_ACTIVE_TARGET` | 已到位保持，等待新鲜完整输入核验；到位后 2 秒期限不因保活延长。 |
| `ACTIVE` | 全轴跟随；J6/J7 从实测姿态过渡，手指先完成固定首次目标，再使用实时输入。 |
| `PAUSED_INPUT` | 输入暂缺，受控减速保持；最长 500 ms，恢复需连续 3 帧满足连续性。 |
| `FAULT` | 本次会话被闭锁，读取原因和新鲜反馈，走显式恢复。 |

接近规划仅检查机械臂和腕部，不包含灵巧手掌体/手指。受检回零使用独立几何检查。左右带手模式共享不可达位置保持与恢复；输入过期、控制器故障和其他错误不属于可达性保持。

## 停止与受检恢复

“停止机器人运动”“停止运动 s”“结束计算”都会结束目标流并请求网关停止。页面关闭、控制页面心跳超过 4 秒缺失或刷新控制页面也会停止该会话；第二个页面可监控/停止，不能接管。

左/右臂及双手有独立失能入口。分侧失能前网页先停止整个组合目标流，再对所选硬件失能；以新鲜反馈和 `disable_verified` 为准。手部软件命令失能表示关闭目标跟随，不能等同于电机撤销保持力。头部失能需回读两轴扭矩状态。

单臂带手“受检回零并恢复 IDLE”的顺序：

1. 取得七轴新鲜失能反馈，核验控制器健康；仅在孤立电子急停且满足既有条件时复位。
2. 在机械臂当前姿态检查完整手部归零扫掠，先恢复该侧自然张开零位并核验到位。持续检查七轴失能、反馈新鲜和姿态漂移不超过 0.2°。
3. 手部成功后才规划并执行 J1–J7 回零，最终核验失能、控制器连续三份健康反馈和手部仍在零位，全部成功才进入 `IDLE`。

手部零位是分侧标定的自然张开姿态，不是十轴全部数值 0。前置手部阶段不自动失能仍在承重的机械臂；检查拒绝或取消时七轴不开始运动。手部拒绝且机械臂已验证健康失能时保留 FAULT 和原因，不追加电子急停；显式停止、控制器故障或未知反馈仍按原停止流程处理。

纯单臂直接执行七轴受检回零。仅手恢复核验机械臂失能、手部软件失能和反馈，不发送手臂位置指令。双臂不提供自动恢复。`q` 退出网关包含电子急停；重启进程不能解除实体急停、其他故障或接触卡阻。

## 骨架与数据质量显示

| 骨架层 | 数据来源 |
| --- | --- |
| 原始采集 | 最新有效 PICO Body。 |
| 固定映射 | 当前 Body 经固定坐标变换，仍随新帧运动。 |
| 重定向目标 | 预览/正式计算产生的机器人任务目标。 |
| IK 结果 | 当前关节求解对应的姿态。 |
| 本机计算输出 | 实际输出目标。 |
| 机器人实际反馈 | 新鲜机器人关节反馈。 |

前两层只需采集；后四层需计算或机器人反馈。没有数据时页面保留所选层并显示等待原因。骨架约 20 Hz 轮询，传输频率按 SDK 组件提交与实际 Body 转发计算，不能用绘制频率评估采集。

页面保留真实输入年龄、来源、序号、传输频率、无效/过期/合并数、队列丢弃和必要故障。手部首次目标、实时来源、本机命令、网关已发布命令与实测反馈分别显示。处理耗时和 P95 等性能数据仅由 [独立测试工具](04_TROUBLESHOOTING.md#独立测试与耗时测量)采集，正式网页不展示。

## 腰部、相机和状态含义

腰部调整只在机械臂停止且全部失能时进行。先读取 31/32/33 反馈并使能，单次目标限于最新反馈 ±5°、单圈 0°～360°；±1° 小步为 5°/s、12°/s²，输入目标为 4°/s、10°/s²。URDF 固定姿态对应编码器约 139°/215°/144°，臂使能前核验基准 ±0.2°、速度及错误。调整后须恢复模型基准；页面不提供腰部失能，停止为受控减速。0x0C26 电池提示保留显示，其他错误仍锁定。

相机面板“开启调整”后才允许头部运动，保留原限位、步长、反馈和心跳检查；头部失能会失去支撑力，应由现场托稳。

“已提交”表示请求已发出；“会话运行中”表示进程存在。`IDLE` 不保证控制器健康，FAULT 不保证七轴失能。状态文件约 5 Hz 异步发布，其年龄和浏览器轮询不叠加到 100 ms 输入门限；旧状态文件不能当作当前反馈。升级后功能按钮仍禁用时，核对本机和网关进程的版本/功能标记。
