# 网页遥操作控制台

本文解释网页按钮、模式和状态；每日完整顺序见 [运行手册](03_OPERATION_RUNBOOK.md)，环境安装见 [本机 README](../README.md#环境安装与配置)。

## 启动网页

在仓库根目录运行：

```bash
./laptop_teleop/scripts/run_dashboard.sh
```

打开 **http://127.0.0.1:8080**，保持服务终端运行。启动网页不自动启动设备、使能或运动。重复执行启动脚本会复用已有控制台；后端源码更新后，须结束计算并重启原控制台进程，刷新页面仅更新前端资源。端口被其他程序占用时可用 `--port 8081`。

网页默认 SSH 连接 `esrobo@192.168.10.100`，机器人仓库 `/home/esrobo/Projects/esrobo`，机器人 Python `/home/esrobo/miniconda3/envs/teleop_esrobo/bin/python`；部署常量在 `dashboard.py`，新机器按实际环境修改。

## 页面与模式

| 区域 | 用途 |
| --- | --- |
| 设备与驱动 | 机器人 SSH、CAN 初始化、网关/双手/视觉服务、本机 PC Service 和采集启停。 |
| 遥操作控制 | 模式选择、环境检查、预览、正式计算、人工准备、停止和受检恢复。 |
| 腰部三轴 | 读取反馈、独立使能、小步与角度调整、减速停止。 |
| 实时视觉 | 相机/头部控制，或 PICO 骨架和分层计算结果。 |
| 机器人状态 | 网关阶段、原因、七轴使能、控制器故障、输入年龄和手部状态。 |
| 日志与操作记录 | 采集、本机计算、机器人服务和控制台操作结果。 |

支持单臂＋同侧手、纯单臂、仅单侧灵巧手和双臂模式。仅手模式要求所选 Hand，不要求 Body/IK，机械臂必须始终七轴失能。纯臂模式只要求 Body，实时末端三轴保持实测位置。双臂缺少互碰扫掠检查，自动准备和回零被拒绝。

网关运行时下拉框显示其实际模式并锁定。切换须结束计算、按现场流程停止网关并等待退出，再选择模式启动；下拉框不会改变已运行的进程。

## 连接与服务启动

1. 点击“连接机器人”。首次 SSH 主机密钥先通过终端核对，网页不自动信任未知主机；密码仅用于当前连接，有公钥时可留空。
2. CAN 未就绪时点击“关闭服务并初始化 CAN”。页面先停止计算、请求并核验机械臂失能；腰部正在运行时还须停止并核验三轴停稳，然后关闭相关驱动、网关和手部桥。任一步未确认就中止，不强制重置总线。
3. 带手/仅手模式依次启动“双手 ROS 驱动”“双手通信桥”“双臂遥操作网关”；纯臂可省略双手服务。网关自身持有机械臂驱动，不另启争用 CAN 的控制进程。
4. 查看 `IDLE`、控制器无故障和新鲜反馈。继承电子急停时结束计算，再走受检恢复；CAN 初始化和网关重启均不代表控制器已复位。
5. 本机启动“PICO PC Service”“PICO 全身＋双手采集”。头显佩戴亮屏、追踪应用在前台、Body 与 Hand Tracking 开启。带手模式核对同侧肩肘腕、手指和掌面状态。

相机需要机器人相机驱动与 8766 网页服务，HTTP 经已登录 SSH 通道转发；PICO 骨架来自本机 8765 服务。二者互相独立，SSH 登录成功不证明图像服务已启动。

## 预览、标定与正式运行

先点击环境检查，再预览并采集有效初始参考，核对实际计算目标和各层姿态。预览不发送运动目标；结束预览会请求停止，正式运行前须恢复网关 `IDLE`。

正式计算启动后 `IDLE` 只回送实测机器人姿态。人工点击“使能并准备 e”后，自动准备先核验失能、受检恢复手部自然张开零位，再执行七轴受检回零并验证失能，再进入参考标定。提供期望姿态和完整有效 PICO 输入，首组位姿即锁定为首次目标，目标就绪后自动检查路径并接管，网页不提供手动接管按钮；取消倒计时、稳定窗口和自然张手要求，保留时效与同步检查。

| 网关阶段 | 页面应如何理解 |
| --- | --- |
| `CALIBRATING` | 采集单组有效初始参考；100 ms 时效和组件同步有效。 |
| `CHECKING_ENTRY` | 锁定完整标定目标，认证 J1–J5 和 J6/J7 两段路径；手指保持实测位置。 |
| `APPROACHING` | 50 Hz 分两段受检接近：先 J1–J5 到位并停稳，再 J6/J7 到位。独立保活持续，不改写标定目标。 |
| `WAITING_FOR_ACTIVE_TARGET` | 已到位保持，等待新鲜完整输入核验；到位后 2 秒期限不因保活延长。 |
| `ACTIVE` | 两段接近均已到位，开始全轴实时跟随；手指先完成固定首次目标，再使用实时输入。 |
| `PAUSED_INPUT` | 输入暂缺，受控减速保持；最长 500 ms，恢复需连续 3 帧满足连续性。 |
| `FAULT` | 本次会话被闭锁，读取原因和新鲜反馈，走显式恢复。 |

接近规划仅检查机械臂和腕部，不包含灵巧手掌体/手指。接近到位后的跟随初始化沿用已完成的验证，不重复进行几何核验；仍确认新鲜静止反馈和控制器状态。接受首个 ACTIVE 目标和受检回零保留各自独立几何检查。左右带手模式共享不可达位置保持与恢复；输入过期、控制器故障和其他错误不属于可达性保持。

## 停止与受检恢复

### 有界重新接管与锁存保持（待实机验收）

网关与本机须同时支持 `input_recovery_protocol=1`。`left_input_recovery_verified`、`right_input_recovery_verified` 默认关闭：仅同步代码不会启用更宽恢复条件，必须完成对应侧位置保持实机验收。双臂要求两侧都验收通过；现有双臂启动/回零限制不因此解除。

- `INPUT_WAIT`：等待新鲜输入，最多 500 ms。
- `REACQUIRING`：输入恢复后的限速衔接阶段；不再限制相对中断前或相邻源目标的角度差，统一要求连续 3 个独立新鲜有效帧，输入资格确认仍有 3 秒期限；恢复开始后连续成功发送 3 个有效帧即结束恢复，不等待运动中的手臂和手指精确到位。首次腕部运动已在 APPROACHING 内完成。网页“手限速中”表示手指指令正在限幅，可张手释放；不单凭该提示判定实物接触。
- `HOLD_LATCHED`：网页显示“已停止并保持”。已验收的机器人端独立减速、持续保持，拒绝新目标；本机程序退出或网络客户端消失不会解除该锁存。保持是否正常必须看持续新鲜反馈，不能凭使能位推断。

锁存后使用“受检回零并恢复 IDLE”按原有机械支撑确认、失能核验和受检恢复流程处理。显式 s/x 急停、硬件故障和网关进程退出仍走急停路径；该功能不能保证断电、CAN 故障或控制器故障下不下落。

腕部诊断区域显示 J5–J7 的速度、加速度和领先量刹停限制占比；占比可以重叠。当前本地候选限制为36°/s、100°/s²；完成接管验证后的实时跟随允许领先量为15°，准备、首次接管和回零仍为10°；不再附加回零速度缩放。新参数尚须实机验收。未验收时页面明确提示自动重新接管未启用。

“停止并保持”用于正常 ACTIVE 跟随：先向网关发送独立 `h` 请求，机器人沿原轨迹状态受控减速并锁存保持，再结束本机计算；不会附加急停或失能。受限于减速过程，停点可能略超出点击瞬间的位置。停止后不自动续动，可执行受检恢复。顶部“紧急停止（急停）”以及终端 `s/x` 保留显式急停。

本机收到合同校验通过的 `HOLD_LATCHED` 后，以“已停止并保持”正常结束（退出码 0），记录 `controlled_stop` 事件，不再记录为运行故障或提示“restart after local recovery”。真实 `FAULT` 和合同不匹配仍按错误处理；显示文案不替代机器人端持续反馈核验。

普通保持按钮要求 `controlled_stop_protocol=1` 且该模式已完成保持验收；当前已验收配置为左臂。旧网关、未验收模式、准备/接近/回零阶段均不提供此按钮，需立即中止时使用顶部急停。“结束计算”、页面关闭、控制页面心跳超过 4 秒缺失或刷新控制页面会结束目标流：已验收的新网关进入机器人端锁存保持，未验收端仍按原故障停止策略处理。第二个页面可监控/停止，不能接管。

左/右臂及双手有独立失能入口。分侧失能前网页先停止整个组合目标流，再对所选硬件失能；以新鲜反馈和 `disable_verified` 为准。手部软件命令失能表示关闭目标跟随，不能等同于电机撤销保持力。头部失能需回读两轴扭矩状态。

“单独失能”不清除控制器急停、软件故障锁存，也不恢复 `IDLE`。左/右臂状态同时显示使能数量及故障，例如“已失能 0/7 · 故障：EMERGENCY_STOP”；使能反馈缺失时显示“使能状态未确认”。七轴新鲜失能已确认但运行位置因急停后位移被旧锚点拒绝时，网页允许提交显式恢复，由机器人端重新读取并核验当前位置；不会使用被拒绝的角度直接运动。仍使能的保持回零继续要求健康、新鲜的位置反馈；混合使能或未知状态仍拒绝。

“受检回零并恢复 IDLE”不会隐式发送停止或失能，按当前状态选择流程：

- **健康的 `HOLD_LATCHED`、七轴使能**：要求网关声明 `hold_return_protocol=1`，新鲜反馈及控制器/驱动正常。从已提交轨迹受控减速并核验静止，保持使能先受检恢复灵巧手自然张开零位，再规划并执行 J1–J7 回零，到位后才失能。张手期间持续核验七轴使能、控制器、力矩、反馈时效及相对起点不超过 0.2° 的漂移。规划拒绝时，仅在重新核验静止、反馈、领先量、力矩和控制器健康后恢复锁存保持。

近零位回零例外：以所选侧七轴新鲜 URDF 实测角度判定，每轴距零位不超过 `full_arm_return_tolerance_deg`（当前 1.5°）时，不构建或检查手指扫掠包络；仍检查机械臂、腕部和手掌几何，保留手部反馈新鲜、自然张开到位、控制器、力矩、取消及相对锚点 0.2° 漂移保护。手部阶段若离开零位容差立即拒绝。先手后臂的顺序不变；手部核验完成后，机械臂经连续静止零位复核即可结束，已失能时不重新使能，保持使能时仅在到位与健康核验通过后失能。例外仅用于回零（含自动准备），退出后恢复完整手部几何；非零位回零、实时跟随和 ACTIVE 接管不采用该例外。
- **七轴已失能**：核验新鲜反馈和控制器健康；仅按既有条件复位孤立电子急停。失能静止复位不以碰撞几何通过为前提，不发送使能或运动；仍要求七轴新鲜失能反馈、关节范围、无其他控制器/驱动故障，复位后连续三帧健康失能且漂移不超过 0.2°。带手模式先在当前位置检查完整手部归零扫掠、自然张开并验证，再规划执行七轴回零，到位后失能。手部阶段持续验证失能、反馈新鲜和臂漂移不超过 0.2°。
- **控制器故障但七轴仍使能、混合使能或未知状态**：拒绝回零，不自动失能。先核对故障和现场支撑，再使用独立失能入口处理。

手部零位是分侧标定的自然张开姿态，不是十轴全部数值 0。完整回零、失能和手部核验成功才进入 `IDLE`。手部拒绝且机械臂已验证健康失能时保留 FAULT 和原因，不追加电子急停；显式停止、控制器故障或保持能力失效仍按原故障处理。新版连续保持回零必须经现场受控验证，离线测试不代表已验证承重效果。

显式恢复时，如果七轴已经失能且在现有零位容差内，继续核验连续新鲜静止零位样本、控制器健康和手部状态后直接恢复 `IDLE`；不为零距离回零重新使能。非零位仍须完整规划、执行和到位失能。

恢复要求网关报告 `return_protocol=3`，不以已有接管协议推断回零代码已更新。带手恢复发现控制器或驱动反馈缺失时，先有界请求 CAN 遥测，再核验真实七轴；请求不使能、不发送位置目标。仍无反馈时保留拒绝原因，不强制清成 IDLE。


纯单臂直接执行七轴受检回零。仅手恢复核验机械臂失能、手部软件失能和反馈，不发送手臂位置指令。双臂不提供自动恢复。`q` 退出网关包含电子急停；重启进程不能解除实体急停、其他故障或接触卡阻。

## 骨架与数据质量显示

| 骨架层 | 数据来源 |
| --- | --- |
| 原始采集 | 最新有效 PICO Body。 |
| 固定映射 | 当前 Body 经固定坐标变换，仍随新帧运动。 |
| 重定向目标 | 预览/正式计算产生的机器人任务目标。 |
| IK 结果 | 当前关节求解对应的姿态。 |
| 本机计算输出 | 实际输出目标。 |
| 机器人实际反馈 | 新鲜机器人关节反馈。 |

前两层只需采集；后四层需计算或机器人反馈。没有数据时页面保留所选层并显示等待原因。骨架约 20 Hz 轮询，传输频率按 SDK 组件提交与实际 Body 转发计算，不能用绘制频率评估采集。

采集频率使用最近两秒内的样本，断流后归零；手部样本或映射结果超过 100 ms 时，诊断显示 `stale`，不再保留 `tracking`。PC Service 重启后若头显未自动重连，需要在头显应用中重新连接本机；以 Body 序号持续推进确认恢复。

页面保留真实输入年龄、来源、序号、传输频率、无效/过期/合并数、队列丢弃和必要故障。手部首次目标、实时来源、本机命令、网关已发布命令与实测反馈分别显示。处理耗时和 P95 等性能数据仅由 [独立测试工具](04_TROUBLESHOOTING.md#独立测试与耗时测量)采集，正式网页不展示。

## 腰部、相机和状态含义

腰部调整只在机械臂停止且全部失能时进行。先读取 31/32/33 反馈并使能，单次目标限于最新反馈 ±5°、单圈 0°～360°；±1° 小步为 5°/s、12°/s²，输入目标为 4°/s、10°/s²。URDF 固定姿态对应编码器约 139°/215°/144°，臂使能前核验基准 ±0.2°、速度及错误。调整后须恢复模型基准；页面不提供腰部失能，停止为受控减速。0x0C26 电池提示保留显示，其他错误仍锁定。

相机面板“开启调整”后才允许头部运动，保留原限位、步长、反馈和心跳检查；头部失能会失去支撑力，应由现场托稳。

“已提交”表示请求已发出；“会话运行中”表示进程存在。`IDLE` 不保证控制器健康，FAULT 不保证七轴失能。状态文件约 5 Hz 异步发布，其年龄和浏览器轮询不叠加到 100 ms 输入门限；旧状态文件不能当作当前反馈。升级后功能按钮仍禁用时，核对本机和网关进程的版本/功能标记。

回零失败提示仅展示阶段与短原因，完整反馈和碰撞详情见机器人网关日志。状态包精简时显示“完整记录见机器人网关日志”，不表示机器人故障已消除；实际状态仍以新鲜反馈为准。

左手十轴重定向运行时，状态栏显示十轴目标／反馈、求解耗时、模型对捏误差和限位轴数。误差是按掌宽归一化后的模型拟合指标，不是实机指尖测量。原始姿态和三维回放见 [左手十轴重定向](07_CODE_AND_COMPUTATION.md#左手-l20lite-十轴重定向)。
### J6/J7 稳定滤波（2026-10-19）

左右臂实时跟随新增独立 J6/J7 稳定层：最低 1 Hz、最高 4 Hz、自适应系数 0.2、1° 连续死区。J5、其他机械臂关节和手指映射保持原样；首次接近与回零不使用新增层。慢速腕部微调会比原来迟缓，2°/s 匀速输入额外滞后约 0.64 秒。该处理减少往返，不提供自动静止锁定。

更新后必须同步两端配置并在停止、失能且反馈新鲜时重启网关和本机配置加载进程；网页刷新不能替代后台重启。详情见 [算法与离线验收](07_CODE_AND_COMPUTATION.md#j6j7-独立稳定滤波)。
