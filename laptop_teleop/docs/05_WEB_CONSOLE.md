# 网页遥操作控制台

## 1. 一条命令启动

已配置本机 Conda/ROS/设备 SDK 后，在仓库根目录执行：

```bash
./laptop_teleop/scripts/run_dashboard.sh
```

浏览器打开 **http://127.0.0.1:8080**。不必先激活 Conda，也不必另开 SSH 终端、端口转发或多个采集终端。保持首次启动服务的终端运行。重复执行命令会提示“控制台已在运行”并正常退出，直接打开提示中的地址即可，现有连接和程序继续运行。若端口被其他程序占用，可用 `--port 8081` 并打开对应地址。

首次从旧版本升级，在本机更新依赖一次：

```bash
PYTHONNOUSERSITE=1 /home/ddc/miniforge3/envs/esrobo_laptop/bin/python -m pip install -e ./laptop_teleop
```

启动控制台只开启本机网页，不自动启动设备、使能、回零或运动。SSH 固定连接 `esrobo@192.168.10.100`，机器人仓库为 `/home/esrobo/Projects/esrobo`，机器人 Python 为 `/home/esrobo/miniconda3/envs/teleop_esrobo/bin/python`。这些部署值集中在 `src/esrobo_laptop/dashboard.py` 顶部。

## 2. 页面区域

- 左侧“设备与驱动”：SSH 登录、机器人/本机服务启停、CAN 初始化和 PICO 身体/手腕标定说明。本机只需 PICO PC Service 与全身/双手采集。点击 CAN 初始化后，页面按顺序停止计算、核验失能并关闭网关、双手通信桥和驱动；任一步未确认都会中止初始化。机器人端分别显示双臂网关、左臂、右臂、双手、头部、相机和网页桥；左臂、右臂、双手及头部均有独立失能入口。
- 顶部“遥操作控制”：双臂双手、单臂带手、纯单臂、仅左灵巧手和仅右灵巧手模式；预览、正式计算、人工使能、停止运动和结束计算。故障后恢复按钮紧邻控制按钮：仅灵巧手模式核验失能与反馈后回到 `IDLE`，单臂模式执行原有受检回零；双臂模式不提供自动恢复。页面最上方也保留随时可用的“停止机器人运动”。页面刷新后，下拉框从正在运行的机器人网关参数恢复当前模式。
- 中间“实时视觉”：用“相机与头部 / PICO 骨架”按钮切换。相机页包含彩色/深度画面、两轴反馈、目标计数、±10 小步、开启/锁定调整和头部舵机失能；骨架页包含 PICO 原始、固定映射、重定向目标、IK 结果、本机计算输出和机器人实际反馈六层。前两层随 PICO 采集显示，后四层需要预览或正式计算正在运行且输入完整；等待数据时页面保留所选层并显示原因，不再自动跳回原始层。
- 右侧“机器人状态”：网关模式、原因、各轴角度/使能、控制器故障、手部数据、输入新鲜度和参考状态。安全门指示会同时提示控制器、输入数据和跟随状态。
- 底部“运行日志与操作记录”：PICO 身体/双手采集、本机计算、机器人 tmux 输出和控制台事件。

所有按钮返回“已提交”只表示命令已发出，程序是否就绪、运动是否停止须看日志和实时反馈。“会话运行中”表示 tmux 会话存在，不等同于传感器数据有效。

## 3. 连接与启动机器人

1. 输入机器人 SSH 密码，点击“连接机器人”。密码仅用于当前请求，不保存在 YAML、日志、浏览器存储或仓库中；配置了 OpenSSH 密钥时可留空。
2. 首次 SSH 主机密钥须已在本机 `~/.ssh/known_hosts` 中被确认。现有机器人已经完成这一步。若换了机器人或重装系统，先按文档 02 验证主机指纹；网页不会自动信任未知主机。
3. 在顶部选择本次模式。**已运行的网关不会随下拉框自动切换。** 网关运行时下拉框锁定并显示其真实模式；更换模式需结束计算、关闭网关、等待会话退出，再选择并启动网关。
4. 查看 CAN 状态。尚未初始化时，点击“关闭服务并初始化 CAN”，输入机器人 sudo 密码。页面先结束本机计算，再向网关请求全部失能，核对新鲜的七轴失能反馈，然后依次关闭网关、双手通信桥、双手 ROS 驱动；只在三者都退出后执行初始化。若失能核验或退出等待失败，CAN 不会被重置。
5. 含手及仅灵巧手模式依次启动“双手 ROS 驱动”“双手通信桥”“双臂遥操作网关”；纯单臂模式可不启动双手驱动与桥。仅灵巧手网关仍打开所选侧机械臂驱动用于验证七轴持续失能，但不会使能或发送手臂目标。左臂和右臂驱动由同一个网关进程持有，因此对应卡片只显示分侧状态和独立失能，不再启动会争用 CAN 的第二个进程。现有同名 tmux 会话会被识别，不会重复启动。
6. 网关应为 `IDLE`，双方反馈有效。若显示 `EMERGENCY_STOP`，先按厂家现场流程处理急停，网页不会清除或绕过控制器故障。
7. 需要视觉时，依次启动“头部两轴驱动”“RGB / 深度相机”“相机网页服务”。头部驱动启动是只读状态；只有在相机面板点“开启调整”后才允许调整。相机 HTTP 通过已登录的 SSH 通道转发，不需要手工运行 `ssh -L`。切换到“PICO 骨架”时页面加载本机骨架服务；显示“调试服务断开”时先启动 PICO 数据采集，并确认本机 `127.0.0.1:8765` 服务可用。

## 4. 启动本机与完成标定

切换左侧“本机端”：

1. 升级时先按 [PICO 统一输入操作文档](06_PICO_HAND_INPUT.md) 安装 SDK 扩展，并停止旧 SenseCom、SenseGlove ROS 和手套桥。
2. 启动 **PICO PC Service**，在头显内开启 Body/Full Body 与 Hand Tracking，连接本机；启动 **PICO 全身 + 双手采集**。摘下手套，保持双手在头显识别范围内。
3. 日志分别显示 Body 与左右 Hand 状态。全身 24 关节提供身体与手腕姿态，独立 26 点 Hand 流提供五指；任何一路都不能替另一条续期。
4. 预览时将前臂抬到胸前、肘部自然弯曲、双手保持在头显视野内，等待自动参考；无需输入手套序列号或完成手套 IMU 标定。仅灵巧手模式不需要身体参考。
5. 右侧逐项确认当前模式所需输入。带手臂模式要求所选侧“肩肘腕骨架 / 五指追踪 / 手腕整体姿态”；纯单臂只要求 Body；仅灵巧手只显示并要求所选侧“五指追踪”。缺失项会显示“未收到”。

## 5. 预览、开始与使能

1. 先选择遥操作模式，再点击本机“环境检查”。检查命令会跟随当前选择，并列出该模式要求的 PICO 输入通道和机器人服务；仅灵巧手只检查对应侧 Hand 输入且不加载 IK 模型。切换模式后需重新点击检查。
2. 点击“预览计算”，按页面提示保持胸前抬臂姿态。查看“准备姿态”“计算”步骤、数据源年龄和日志；预览会持续计算目标但不发送运动指令。检查完成后可点击“暂停预览”。
3. 结束预览后，网页会发送停止请求，网关进入 `FAULT`。结束本机计算后使用“故障停止后恢复”按钮，等待机器人状态回到 `IDLE`，再启动正式计算。恢复不自动使能。
4. 点击“开始正式计算”。`IDLE` 阶段只回送机器人当前实测姿态，不要求先完成身体参考，也不会产生运动。
5. 点击“使能并准备 e”。单臂＋单手模式下网关先让灵巧手限速张开并核对十轴反馈，再让机械臂按碰撞规划受检回零并验证七轴失能；然后进入 `CALIBRATING`。此时按页面提示把前臂抬到胸前、肘部自然弯曲、双手自然张开。姿态有效后保持约 3 秒，PICO 连续确认稳定姿态并自动发送与机器人零位匹配的首帧，网关再进入 `ARMING` 和 `ACTIVE`。任何阶段均可点击“停止运动”。
6. 双臂模式没有互碰扫掠检查，因此网页会拒绝自动回零使能；先按现场验证的双臂恢复流程处理。仅灵巧手模式只准备并使能所选灵巧手，机械臂反馈必须始终为 `0 / 7`。

每次点击“使能并准备”都会丢弃之前的临时参考，在机器人零位验证后重新采集；PICO 人手不保存单独零位文件。

## 6. 停止、独立失能、恢复与关闭

- 顶部红色“停止机器人运动”和遥操作工具栏中的“停止运动 s”都会先停止本机目标生成，再向网关发送 `s`。任何打开控制台的本机页面均可停止。
- “结束计算”同样停止会话；运行中停止采集程序也会先停止计算。
- 浏览器页面关闭会主动请求停止；浏览器心跳超过 4 秒缺失，服务端会停止该页面启动的计算。计算停止后仍由网关 STOP/lease 及底层控制器处理机械停止。不是硬件急停保证。
- 刷新正在控制的页面会结束旧页面会话；不会自动重新开始。页面会显示正在运行的网关真实模式，避免误按其他模式重新初始化。第二个页面只能监控或停止，不能接管正在运行的计算。
- “左臂失能”“右臂失能”“双手命令失能”分别向网关发送 `dl`、`dr`、`dh`。选择任一分侧失能前，网页先停止整条本机目标流并发送 `s`，避免另一侧继续跟随一个已经失效的组合目标。随后只对所选硬件执行失能；必须以对应反馈中的 `enable_states` 和操作结果为准。
- “头部舵机失能”调用头部驱动的独立失能服务并回读两个舵机。失能后头部会受重力移动，点击前必须托稳相机。重新启用只能走“开启调整”的反馈、限位与心跳门禁，不能通过失能接口反向启用。
- “网关全部失能”发送 `d`，依次尝试失能所持有的机械臂和手。停止后保持 `FAULT` 属于网关的闭锁设计。“恢复与关机”还提供 `z` 单臂受检回零、`q` 退出网关；双臂及仅灵巧手模式的 `z` 会被拒绝。
- 新的“故障停止后恢复”按钮使用网关本地 `r` 命令：仅灵巧手模式不发送回零位置指令，只在机械臂七轴失能、控制器无故障、手部已失能且反馈新鲜时解除 `FAULT`；单臂模式复用 `z` 的受检回零，可能产生真实运动。执行失败继续保持 `FAULT`。恢复到 `IDLE` 后仍需重新开始计算并人工点击“使能并准备”。正在运行的旧网关必须更新代码并重启一次，之后故障恢复无需重启网关。
- 升级期间页面会检查本机控制台与机器人网关的功能标记。旧进程仍在运行时，新的 CAN 初始化或恢复按钮保持禁用；更新代码后分别重启一次本机控制台和机器人网关，按钮才会开放。现有网关尚在运行时，直接再次执行 `run_dashboard.sh` 不会替换旧控制台进程。
- 独立失能返回失败或 `disable_verified=false` 时，表示系统无法从当前反馈证明已经失能。继续托稳对应部件，查看控制器/CAN 和网关日志，不得把按钮请求成功当作硬件失能成功。
- 双臂恢复：确认运动已停止 → `d` 并查看七轴失能反馈 → 按厂家流程处理控制器故障 → `q` → 等网关会话退出 → 重新启动网关 → 确认有效 `IDLE` 和无控制器故障 → 重新标定/开始计算。重启网关不能解除实体急停或替代厂家恢复流程。
- 完成后依次停止本机计算、PICO 采集、PC Service，再停止所需的机器人服务。
- 在唯一启动终端按 Ctrl+C 会停止控制台管理的本机子进程；独立 PC Service 和机器人 tmux 服务按需先在网页停止。SSH 断开后 tmux 服务保留，网关不自动使能。

## 7. 状态与日志的含义

机器人状态来自 **正在运行的网关所打开的 JSONL 诊断文件**，通过 SSH 只读获取，不创建第二个 RobotClient，不抢占 UDP 控制会话。页面以约 1 Hz 更新机器人状态，角度用于监控，非实时伺服反馈。原来的“反馈年龄”已改为“状态距今”，表示从网关采样该状态到当前页面显示所经过的时间；它包含日志采样与页面读取延迟，只用于判断状态是否新鲜，不能作为 UDP 运动链路的单程网络延迟。

本机计算在 `laptop_teleop/log/dashboard_teleop.json` 原子更新约 5 Hz 状态，包含参考就绪、真实输入时间、求解状态、发送数和实测反馈，不含通信密钥或 lease。输入卡片的毫秒数表示计算线程采样时的输入年龄；网页状态文件和浏览器轮询延迟不再叠加到 100 ms 输入门限。程序退出后页面不会把旧文件当作实时数据。网关日志继续留在机器人 `robot_link/log/`。

网页中的采集进程“运行中”仅说明进程存在；新鲜数据须看输入年龄与标定提示。PICO PC Service 单独探测服务进程，因为其启动脚本成功后会退出。

## 8. 验证边界

控制台测试覆盖命令白名单、同源/Host 校验、故障/过期状态拒绝使能、页面所有权、停止顺序、分部件失能和浏览器超时。实际设备运动须在 PICO Body/Hand 数据有效、预览映射确认后进行。相机原有限位、小步、反馈与心跳控制继续由原 `HeadControl` 实现执行，头部失能还要求两个舵机的扭矩状态均回读为关闭。
