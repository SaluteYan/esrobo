# PICO 全身、五指与手腕姿态输入

当前版本统一使用 PICO。摘下 SenseGlove 后操作，确保头显能看到裸手。全身 Body 的 24 关节只提供身体和手腕姿态；五指使用同一 PICO SDK 的 Hand 26 点追踪。机器人端的灵巧手 ROS 驱动和通信桥仍需启动，它们是机器人硬件驱动，与采集手套无关。

## 1. 更新本机 SDK（升级时执行一次）

```bash
cd /home/ddc/DualArmTeleoperation
./laptop_teleop/scripts/install_pico.sh
```

安装脚本自动运行 `patch_pico_sdk.py`，增加左右手原子快照接口，返回独立序号、原始 Hand 时间戳、接收距今、26 点位姿与有效标记。扩展只在对应 Hand 数据实际到达时更新。未更新 SDK 时，采集日志会明确提示缺少接口，不能启动带手跟随。

## 2. 网页操作

1. 先结束旧计算，停止本机手套输入桥、SenseGlove ROS 和 SenseCom。升级后的页面不再提供这三个程序的启动入口。
2. 运行 `./laptop_teleop/scripts/run_dashboard.sh`，浏览器打开 `http://127.0.0.1:8080`。已有控制台时刷新页面；后端升级后需先结束计算，再在原终端 Ctrl+C 并重新运行命令。
3. 机器人端依次启动双手 ROS 驱动、双手通信桥、所需模式网关，确认 IDLE；本机端只需启动 PICO PC Service 和“PICO 全身 + 双手采集”。
4. 头显开启 **Body/Full Body** 与 **Hand Tracking**，连接操作员电脑的局域网地址。本机当前 Wi-Fi 地址为 `192.168.3.24`，可能随 DHCP 改变，可用 `ip -4 addr show wlp0s20f3` 确认。`192.168.10.100` 是机器人地址。PC Service 的头显接入端口为 TCP 63901，本机 SDK 使用 127.0.0.1:60061；不要用 SSH/VS Code 转发占用 60061。
5. 预览时将前臂抬到胸前、肘部自然弯曲、双手置于头显视野内，等待身体与手腕参考。正式计算点击“使能并准备”后，灵巧手先限速张开，机械臂再规划回零；页面再次提示时保持同一姿态并自然张开双手，稳定检测通过后自动跟随。仅灵巧手模式不做身体参考，只检测所选侧自然张手。
6. 检查张手、逐指弯曲与手腕三个方向的预览输出。五指使用初始几何映射，拇指对掌和侧摆需要实机预览确认方向、幅度；机器人原先禁用的手轴仍保持反馈值。
7. 正式运动仍需人工点击一次“使能并准备”。之后的机器人回零、PICO 稳定姿态检测和匹配首帧由状态机完成；不会在页面启动时自行使能，也不再执行 SenseGlove 标定或单独保存 PICO 手部零位。

## 3. 命令行替代流程

不要与网页重复启动同名程序。仅需两个采集/计算终端：

```bash
# 终端 A：服务与统一采集
./laptop_teleop/scripts/xrobotoolkit_service.sh start
./laptop_teleop/scripts/run_pico.sh
```

```bash
# 终端 B：默认双臂双手预览；右臂右手增加 --side right
./laptop_teleop/scripts/run_laptop.sh run --preview
```

停止预览、确认机器人停止并按文档 05 恢复到 `IDLE` 后，去掉 `--preview` 启动正式计算；随后在网页点击“使能并准备”，或在机器人网关终端输入一次 `e`。

## 4. 传输与安全语义

- `PICO → PC Service → SDK → acquisition.py`：Body 与 Hand 分开验证；Body 不可用时仍可诊断 Hand。
- 无名指使用 Hand 16–20 号关节，小指使用 21–25 号关节；两者分别计算屈曲目标并发送到 L10 物理轴 4、5，不再共用同一手指输入。
- 本机 UDP `127.0.0.1:15050`：`kind=pico` 携带全身帧；`kind=pico_hand` 按真实侧携带十轴弧度、独立序号和样本时间，单侧不能冒充另一侧。
- `inputs.py`：拒绝缓存重放、超时、非有限数据、越界手目标；忽略所有旧 SenseGlove 包。带手臂模式要求每侧 arm、hand、wrist 均更新；仅灵巧手模式只消费所选侧 hand。任一必需来源缺失都不产生新目标。
- SDK 优先使用独立 Hand 时间戳；没有该时间戳时，额外要求手部位姿变化，静止缓存会超时。这种旧固件兼容模式可能在完全静止时中止跟随，不能用头部时间戳替代。
- 手腕使用 PICO 坐标变换及腰部参考后的旋转差，左右手分别标定；沿用 45° 总角度和每步 2° 限幅，机器人原有速度、步长、碰撞门禁继续生效。
- `本机 → 192.168.10.100:16000`：手臂模式发送七轴 URDF 弧度及可选 L10 十轴目标；仅灵巧手模式的协议合同和目标包明确标记 `hand_only`，包内只有 L10 十轴 0–255 目标，不含任何机械臂字段。不传原始骨架给机器人。
- ACTIVE/ARMING 期间输入丢失会退出计算并执行原停止机制，重新识别不会自动恢复运动。
- 控制循环配置为 50 Hz，正式控制的频率配置值为 40 Hz；仅灵巧手模式按最近两秒平均并允许 5 Hz 测量容差，实际停止线为 35 Hz，其他模式按最近一秒并允许 0.5 Hz。完整目标间隔不得超过 80 ms；任一条件失败，本机立即结束会话，机器人端仍有独立的 200 ms 目标 lease。手输入新鲜度门限为 100 ms，机械臂和灵巧手反馈新鲜度门限均为 150 ms；LinkerHand ROS 驱动及非阻塞通信桥实测约 59 Hz。网页与状态文件采用低频监控，不参与控制循环时序。

右手四指屈曲在 PICO 自然张手参考后使用 1.25 倍比例增益：近期完整握拳的目标最低约 54–60（机器人闭合端为 0），该增益使同一输入接近闭合端。只改变右手物理索引 2–5 的实时屈曲映射，不改变张开/闭合配置、左手或拇指三轴；机器人原有逐帧速度限制仍生效。

右手拇指另对物理索引 0（屈曲）施加 1.25 倍增益，对索引 1（侧摆）施加 0.60 倍增益。近期会话中 PICO 拇指屈曲最高约 0.28 rad，未用满屈曲行程；侧摆多次接近输入上限 1.40 rad，使目标到达 40–41。该调整以自然张手参考为零点，拇指旋转索引 9、左手、四指、机器人开合端点与速度限制不变。首次使用时先预览逐指对合，再低速确认目标、反馈和实物间距；若目标已加深但实物屈曲仍不足，应检查右拇指轴反馈和机构，不继续提高映射增益。

会话 JSONL 约每 200 ms 记录一次 `pico_hand_input_rad` 和 `pico_hand_reference_rad`，可与同条记录的十轴 `targets`、`feedback` 对照，以区分拇指 PICO 姿态估计、映射幅度与机器人执行问题。该日志采样用于诊断，不参与实时控制。

手指索引采用 [OpenXR Hand 关节顺序](https://registry.khronos.org/OpenXR/specs/1.1/man/html/XrHandJointLocationsEXT.html)，数据字段来自 [XRoboToolkit 协议](https://github.com/XR-Robotics/XRoboToolkit-PC-Service/blob/main/README-CN.md)。
