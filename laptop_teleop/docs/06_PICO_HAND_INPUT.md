# PICO 采集与输入协议

本文描述采集来源、通知、转发、时效及同步。安装和 SDK 重建见 [本机 README](../README.md#环境安装与配置)，按钮操作见 [网页文档](05_WEB_CONSOLE.md)。当前输入来自 PICO，计算端忽略旧 SenseGlove 包；机器人灵巧手 ROS 驱动仍是必需硬件服务。

## 来源与时间

Body 24 关节提供腰部、肩、肘和腕；独立 Hand 26 点提供五指与掌面，不能从 Body 推导五指。左右侧独立验证和计数，一侧不能替另一侧续期。

SDK 只在完整组件提交且序号推进时更新缓存；重复/倒退时钟、残缺或非有限姿态不产生新组件。静止但时钟推进的新姿态仍是有效帧；仅 Head 更新不刷新 Body。消息顶层 `timeStampNs` 用于同包去重，不视为已验证传感器采样时刻或网络延迟。

快照保存本机 `CLOCK_MONOTONIC` 接收时间 `received_monotonic_ns`，Python 使用同一单调时钟计算年龄。它表示 SDK 在本机收到组件的时刻；等待、映射、构包和序列化不能重标时间。Head、Body 与 Hand 不能互相借用时间；来源时钟重置后须重新启动采集。

## SDK 通知接口

补丁通过 `scripts/patch_pico_sdk.py` 和 `pico_component_sample.hpp` 幂等升级，`install_pico.sh` 构建原生 SDK 与绑定。采集要求 `get_tracking_updates_version()==1`，并有 `wait_tracking_updates(after_id, timeout_ms=50)`、`get_tracking_diagnostics()` 和 `close()`。

等待释放 Python GIL，返回通知编号与 Body、左/右 Hand 独立快照；回调只提交缓存、计数和唤醒，不执行 Python、文件或网络操作。兼容 getter 解析仍保留，但正式采集不退回旧采样时间逻辑。旧 SDK 明确拒绝启动并要求重建。

整个采集进程仅初始化一次订阅。退出先停止转发和工作线程，再由所有者调用一次 Python `close()`；原生名称是 `deinit()`，不能直接调用不存在的 Python `sdk.deinit()`。

## 独立转发

主线程等待 SDK 通知，优先构建新 Body 包、直接添加 `laptop_input` 元数据并序列化一次，默认发送上限 90 Hz。超过上限合并为最新有效 Body，不排队补发。

左右 Hand 放入各自容量为一的最新值槽，由单个工作线程做现有映射和掌面计算；拥堵覆盖尚未处理的旧样本并计数。映射后、发送前重检真实年龄，过期/无效/重复 Hand 不输出有效控制输入。录制、终端输出和网页诊断通过有界后台处理，不能使 Body 等待手部计算。

UDP 默认本机 `127.0.0.1:15050`：

| 类型 | 内容 |
| --- | --- |
| `kind=pico` | Body、肩肘腕骨段、独立序号、同包时钟、真实接收时间与年龄。 |
| `kind=pico_hand` | 每侧十轴手指弧度、掌面、独立序号和真实时间。 |

`inputs.py` 在锁外解析，按有界批次保留各组件最新有效帧；提交重新核验年龄，旧/无效包不覆盖新的有效组件。控制线程只复制必要快照，重定向和诊断在锁外。Body/Hand 历史均有界。

## 完整性与参考

带手模式要求同侧 Body、Hand、掌面完整，年龄不超过 100 ms，配对间隔不超过 40 ms。掌面参考取首组有效配对数据，不要求连续帧数或姿态稳定；掌面退化不使用默认轴。仅手模式不要求 Body/掌面参考，纯臂不要求 Hand。

掌面使用腕点 1→中指 MCP 12 为指向、小指 MCP 22→食指 MCP 7 为横向，叉积为法向。无名指取 16–20 点，小指取 21–25 点，分别映射物理轴 4、5。Hand 的十轴角度和掌面是同一组件，不用旧 Hand 拼接新 Body 伪造完整性。

手腕使用掌面相对于 Body 前臂的绝对姿态，零位附近 J5 翻掌、J6 侧摆、J7 弯腕。初始姿态参考与目标生成见 [计算逻辑](08_CODE_AND_COMPUTATION.md#映射与逆运动学)。左手改用原始 26 点 URDF 十轴拟合，右手保留屈曲 1.25、拇指侧摆 0.60 增益。各侧反馈标定和右拇指止点独立，详见 [左手十轴重定向](09_LEFT_HAND_RETARGET.md)。

## 运行与诊断

```bash
./laptop_teleop/scripts/xrobotoolkit_service.sh start
./laptop_teleop/scripts/run_pico.sh
```

头显连接本机当前局域网 IP；头显到 PC Service 为 TCP 63901，本机 SDK 为 127.0.0.1:60061。不要用 SSH/编辑器转发占用 60061。上游地址随网络改变，使用 `ip -br address` 确认。

骨架页显示 SDK Body/左右 Hand 提交频率、Body 转发频率、手部映射频率、序号、年龄和合并/无效/过期/发送失败数。提交频率高但存在突发不等于均匀到达。50 ms 网页轮询不参与控制频率计算。

均匀模拟 60/74/90 Hz 的验收目标是至少 95% 有效新 Body 转发，通知到发送 P95 不超过 10 ms；必须通过独立测试工具测量，不能从网页刷新推算。真实采集和真实 IK 预览各测 60 秒，标记上游空档和未启用组件，不宣称本机改造消除了头显/PC Service 停顿。工具与启动条件见 [故障排查](04_TROUBLESHOOTING.md#独立测试与耗时测量)。
